# GitHub Actions（run: 21119317750）失敗の原因調査と修正Plan

## 目標
- GitHub Actions の「RSS to Notion」ワークフローが `schedule` 実行（毎週）で安定して成功する状態にする
- 失敗要因（OIDC/inputs不整合）を解消し、再実行で成功を確認できるようにする

## 背景
- 指定の Actions run（`21119317750`）が `rss-notion` ジョブで失敗している
- 主因は以下2点：
  - `anthropics/claude-code-action@v1` が GitHub token セットアップ時に OIDC token を取得できず失敗（`id-token: write` が無い旨のエラー）
  - 同 Action に `allowed_tools` が渡されているが v1 では未対応（`Unexpected input(s) 'allowed_tools'`）
- 対象箇所は `.github/workflows/rss-feeder.yml` の Step「Filter articles with Claude」

## スコープ
- やること：
  - `.github/workflows/rss-feeder.yml` の Claude Action 設定を v1 仕様に合わせて修正
  - OIDC 失敗を回避するための認証/権限設定を追加（いずれか）
  - 必要な Secrets/前提の確認項目を明文化
- やらないこと：
  - `scripts/*.js` のロジック変更（RSS収集/Notion保存処理の改修）
  - Notion DB スキーマ変更
  - 依存関係の追加・大規模リファクタ

## 前提 / 制約
- GitHub 側に `NOTION_TOKEN`, `FEEDER_DB_ID`, `READER_DB_ID` は設定済み（未設定なら先に設定が必要）
- Claude 実行のための認証情報（例：`ANTHROPIC_API_KEY` 等）が用意できること
- ワークフローは `cron` が UTC 基準（現在 `0 22 * * 0`）で動く

## 変更内容（案）
### データ / バックエンド
- `.github/workflows/rss-feeder.yml` の `anthropics/claude-code-action@v1` step を修正
  - OIDC 失敗の解消（推奨）：`with.github_token: ${{ github.token }}` を明示して OIDC 依存を外す
  - 代替案（OIDC を使う場合）：ジョブ（またはワークフロー）に `permissions: id-token: write` を追加（※ `contents: read` も明示して権限不足を避ける）
  - `allowed_tools` は v1 の入力として無効なので削除
    - もしツール許可を明示したいなら `claude_args` に寄せる（v1 の思想に合わせる）
- Claude 側の認証入力を明示（どれか1つ）
  - `with.anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}`（一般的）
  - もしくは `with.claude_code_oauth_token: ...` を使う運用ならそれに合わせる

## リスク / エッジケース
- `ANTHROPIC_API_KEY`（または OAuth token）が未設定だと、OIDC問題を直しても Claude step が別エラーで失敗する
- Claude の出力が JSON として壊れると `store-to-notion.js` 側で落ちる可能性（生成物の妥当性チェックを強化したくなるが今回はスコープ外）
- `permissions:` を追加する場合、指定漏れで `actions/checkout` などが権限不足になるリスク（`contents: read` を明示して回避）
